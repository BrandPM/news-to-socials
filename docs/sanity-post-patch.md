# Patch — src/sanity/schemas/post.ts

This is the schema diff Andriy applies in the Lovable project to support
the pipeline. **Pipeline-friendly fields are added; existing fields are
not touched.** All new fields are optional / have defaults, so existing
posts continue to work.

After applying: in Sanity Studio the new fields appear in the post editor.
The pipeline's `SanityPublisher.publish_draft` populates them automatically;
human-authored posts can leave them empty.

## What to add

Insert the five `defineField(...)` blocks **after** the `publishedAt` field
and **before** the `tableOfContents` field. Concrete diff below.

```diff
     defineField({ name: "publishedAt", title: "Published At", type: "datetime", validation: (R) => R.required() }),

+    // --- Pipeline-managed fields (ADR-018) ----------------------------
+    defineField({
+      name: "keyTakeaway",
+      title: "Key Takeaway",
+      type: "text",
+      rows: 2,
+      description: "One-sentence summary; used in social-media captions and as excerpt fallback",
```

## How to apply

1. Open Lovable for the icon.finance project.
2. Open `src/sanity/schemas/post.ts`.
3. Paste the five `defineField(...)` blocks where shown above.
4. Commit the change with message: `feat(sanity): pipeline-managed fields per ADR-018`.
5. Deploy the studio (`npm run build` + `npm run deploy` if standalone, or
   automatic if Lovable redeploys on commit).
6. Verify in `/studio` — a new post should now show: Key Takeaway, Cover
   Image Alt Text, Source URL, Generated By. (Topic ID is hidden but
   present in the document JSON.)

## Why each field

| Field | Why we need it |
|---|---|
| `keyTakeaway` | One-sentence summary the pipeline produces alongside the body. Used to populate `excerpt` if missing, and as the basis for the Wave 2 Facebook/Instagram caption. |
| `coverImageAlt` | The existing schema only has alt-text **inside** body images. We add it to the cover, both for accessibility and to feed the FB/IG `alt` parameter in Wave 2. |
| `sourceUrl` | Compliance & tracking — we always know which news peg produced a piece. Read-only so Andriy can't accidentally edit it; if a post needs a different source it's a different post. |
| `topicId` | Stable hash of the original source story. Pipeline dedups against this to avoid republishing the same peg twice on the same brand. Hidden in UI — no operator value. |
| `generatedBy` | Filter in Studio for analytics ("which of our recent posts are AI-generated?"). Pipeline always writes `pipeline`; human-authored posts default to `human`. |

## Backwards compatibility

* All new fields **optional** — old posts continue to work and to render
  on `/insights` exactly as before.
* No existing field renamed, removed, or changed.
* `excerpt` keeps working as today; the pipeline fills it from
  `keyTakeaway` when one is provided.

## Tests / acceptance

After applying:

1. Open `/studio` → create a new test post manually → all new fields
   visible, post saves and publishes.
2. Run the pipeline in `--dry-run` mode: the printed document JSON
   contains all new fields with sensible values.
3. Run the pipeline against a real RSS feed → in Studio a new **draft**
   appears with all fields populated.

## Rollback

If anything is wrong: remove the five `defineField(...)` blocks. The
pipeline will start failing for the new fields, but existing posts and
the manual workflow continue to work.
